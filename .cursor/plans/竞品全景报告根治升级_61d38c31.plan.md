# 竞品全景报告根治升级

## 实测根因（run_a3fd92438635，landscape/quick/已 completed）

报告正文仅 3799 字、5 节，全部是趋势/机会/建议，**没有逐产品规格、定价、对比矩阵**。逐层取证后确认四层串联根因：

1. **discovery 角色判定被全局意图污染（主因）**：trace 里 7 个竞品 `candidate_role` 全是 `trend_reference`/`upstream_supplier`，**0 个核心角色**。`_infer_candidate_role`（[discovery.py](backend/app/agents/nodes/discovery.py) L209-234）把 run 级 `analysis_intent`（含"发展趋势"）拼进**每个**候选判定文本，`_DISCOVERY_TREND_HINTS` 含"趋势"→ 全员命中 → 全判 trend。
2. **landscape 无核心兜底**：core 集空 → `_select_discovered_competitors_for_research`（[planner.py](backend/app/agents/nodes/planner.py) L408-436）的 `deepdive_core` 空 → **无任何竞品拿到三件套深挖**，7 个 research 任务全是浅层 `market_players/product_categories/key_features`。
3. **证据质量门形同虚设**：`RESEARCHER_LOW_SEMANTIC_MIN_CHARS=0`、blocklist 仅 linkedin/登录页、无竞品名 grounding、`quality_floor` 兜底写回垃圾 → 混入 x.com 赌博 spam、裸首页、book118/xun296 目录；证据 11/23 压在 Livis，其余竞品被 extractor 标 `not_applicable_for_archetype`。
4. **writer landscape 框架反对列产品**：[prompts.py](backend/app/service/llm/prompts.py) L1474-1480 明确要求"用产品作 illustrative evidence、不做 apples-to-apples comparison rows"，且无强制的代表产品/画像/对比矩阵 section；三件套 knowledge 也从未注入 writer（writer 只读 evidence+conclusions）。

> 结论：不是 writer naive，而是上游零深挖 + 证据是垃圾 + writer 结构本身被设计成趋势散文。必须四层同治。

## 统一报告骨架：一套商业级骨架，两种 archetype 侧重（核心补全）

外部调研结论（Gartner Magic Quadrant、Forrester Wave 0-5 加权打分→Leaders/Strong Performers/Contenders、CB Insights ESP、infomineo/prospeo/contify 等 CI 实战指南）一致指向：**comparison 与 landscape 不是两套报告，而是同一商业级交付物的两种侧重**。用户愿意付费的核心永远是三个 artifact：①填满（非空白）的对比矩阵（功能/定价/口碑）②2x2 定位图（暴露白空间）③逐竞品 battlecard（含 why-win / why-lose 诚实评估 / 定价 / 可溯源证据）。差异只在"谁进深挖"和"叠加哪层宏观视角"。

统一骨架（两 archetype 共用，固定 section 顺序）：
1. 执行摘要 — 3-5 条"战略含义"而非数据点，结尾给明确决策建议（最后写）
2. 竞品分层 / 定位 — landscape：角色分层地图（Strategic Group：core/adjacent/substitute/upstream/trend）+ 2x2 定位；comparison：2x2 定位 + 我方位置
3. 逐竞品画像（battlecard） — 概览 / 定位 / 优势 / 劣势(诚实) / 定价 / 代表证据 / 威胁；comparison 覆盖**全部点名竞品**，landscape 覆盖 **core top-N**
4. 三件套对比矩阵 — 功能矩阵 + 定价对比 + 口碑情绪，**确定性渲染成表格**（核心 artifact）
5. 趋势与机会 — landscape 重点（可加轻量 Porter 五力 / 市场结构）；comparison 轻量带过
6. 战略建议 — 每条含负责人 / 时间线 / 预期影响 / 所需资源
7. 数据来源、方法论与数据缺口 — 每节标 confidence(full/partial/empty)、每条 claim 可溯源、标采集日期

archetype 差异：
- comparison（同质可比，点名或发现）：三件套深挖**全部**竞品；强调 head-to-head 矩阵 + 我方位置 + why-win/why-lose；趋势从简。
- landscape（异质 / 赛道扫描）：先角色分层地图 + 趋势 / 五力；**自动选 core top-N**（无人工）做三件套深挖；外围竞品只挂简介 + 趋势。

RivalLens 已与商业标准对齐、直接复用（不重造）：
- 覆盖状态 complete/partial/insufficient_data/not_applicable = 商业报告要求的"confidence-scored + 诚实标缺口"
- evidence_ids 行内引用 = "每条 claim 可溯源"
- watchlist 同竞品两次 run 的 conclusions/knowledge diff = CI 最值钱的 "delta / 变化情报"

待补 gap（Phase 3 落地）：对比矩阵表格、2x2 定位、逐竞品 battlecard、prioritized SWOT、(可选) 0-5 打分分层、统一骨架本身。

## Phase 1 — discovery 角色去污染 + 核心兜底（根因①②）

- [discovery.py](backend/app/agents/nodes/discovery.py)
  - `_infer_candidate_role`/`_reconcile_candidate_role`：停止把 run 级 `analysis_intent`、`domain_context` 拼进**逐候选**角色推断；只用 candidate-specific 文本（`candidate_name` + `relevance_reason`）。趋势/媒体词只在候选自身 reason 命中时才判 `trend_reference`。
  - 新增核心兜底：landscape 下 reconcile 前若 core 角色数为 0，将相关性排序 top 候选（排除明确 upstream/媒体机构）提升为 `adjacent_competitor`。
- [planner.py](backend/app/agents/nodes/planner.py) `_select_discovered_competitors_for_research`
  - landscape 且 `len(deepdive_core)==0` 时，从非 upstream 候选按序补足到 `min(landscape_core_deepdive_n, max_competitors)` 进入 `deepdive_core`，杜绝"零深挖"退化。
- 测试 [test_plan_reconcile.py](backend/app/tests/test_plan_reconcile.py)：全 trend_reference 输入仍产出 N 个三件套深挖；新增 discovery 角色单测（同一含"趋势"意图下产品候选不被误判 trend）。

## Phase 2 — 证据质量门（根因③）

- [researcher.py](backend/app/agents/nodes/researcher.py)
  - `RESEARCHER_LOW_SEMANTIC_MIN_CHARS` 由 0 恢复为有效门槛（约 120-160），对 search snippet 同样生效。
  - 新增 URL 拒绝：含 `/search?q=`、x.com/twitter 搜索页、无有效 path 的裸首页、文档农场/目录站。
  - 新增竞品名 grounding：evidence 标题或正文须提及竞品名/别名才落库（复用 `_text_mentions_candidate`）。

- [source_quality.py](backend/app/service/collector/source_quality.py)：扩展 `BLOCKED_HOST_SUFFIXES`/`BLOCKED_PATH_MARKERS`（x.com、book118.com、xun296.com、`/search`、`/webdir` 等）+ 裸首页判定。
- [subgraphs/researcher.py](backend/app/agents/subgraphs/researcher.py)：rerank query 改为 `{competitor} {dimension} {research_topic}`，低分必 drop。
- 测试 [test_researcher_evidence.py](backend/app/tests/test_researcher_evidence.py)：spam/裸首页/无关内容被拒、competitor grounding 通过与拒绝。

## Phase 3 — 统一商业级报告骨架（comparison + landscape 共用）（根因④ + 目标结构）

- [agent_outputs.py](backend/app/schemas/agent_outputs.py) `resolve_writer_target_sections`：按 archetype 强制统一骨架，不再靠 analyst LLM 自由选 section。
  - 共用：`executive_summary`(顶层字段) / `competitor_profiles` / `comparison_matrix` / `positioning_map` / `strategic_recommendations`
  - landscape 追加：`market_landscape_map` / `trend_summary` / `opportunity_map`
  - comparison 追加：`self_positioning`(我方位置 / 差异化)
- [writer.py](backend/app/agents/nodes/writer.py)：writer 当前只读 evidence+conclusions，需新增读取持久化三件套 knowledge（features/pricings/feedback/personas），并**确定性渲染**（不靠 writer LLM 自由发挥），两 archetype 一致：
  - `comparison_matrix`：功能矩阵 / 定价对比 / 口碑情绪 三张 Markdown 表（竞品为行、维度为列，缺失标 confidence）。
  - `competitor_profiles`：逐竞品 battlecard（概览 / stance / 优势 / 劣势 / 定价 / 代表证据），comparison 全量、landscape core top-N。
  - `positioning_map`：报告为 Markdown 不渲染图表，用结构化文本 2x2（两轴 + 四象限归属 + 白空间）。
  - LLM 仍负责执行摘要 / 趋势 / 机会 / 建议等叙述段，但矩阵与画像由代码兜底"有数据必出表"。
- [prompts.py](backend/app/service/llm/prompts.py)：改写两 archetype framing——
  - landscape：删除"产品仅作 illustrative evidence、不做 apples-to-apples 对比行"旧指令，改为先分层地图+代表产品、再矩阵、再趋势/机会/建议。
  - comparison：强化"全部竞品三件套 + head-to-head 矩阵 + 我方位置 + why-win/why-lose 诚实评估"。
  - 共用：执行摘要写战略含义、建议带负责人/时间线/影响、SWOT 仅作 3-5 条 prioritized 汇总。
- 测试：writer 表格/画像/定位确定性渲染单测、两 archetype `target_sections` 单测、analyst 输出单测。

## Phase 4 — QA 新增确定性护栏（防回归，两 archetype 适用）

- [qa/engine.py](backend/app/service/qa/engine.py) 新增（已读取 `analysis_archetype`，L691）：
  - 三件套覆盖：comparison 全部点名竞品 / landscape core top-N 的功能·定价·口碑 coverage 低于阈值 → reject 回 supervisor 触发补研究。
  - 证据均衡：单竞品证据占比过高（如 >60%）/ 多个目标竞品 0 证据 → reject 或 warning。
  - 来源质量：spam / 裸首页 / 搜索页 evidence 占比超阈值 → reject。
  - 结构完整：统一骨架必备 section（矩阵 / 画像）缺失或为空 → reject。
- 测试 [test_qa_rules.py](backend/app/tests/test_qa_rules.py) 覆盖新 gate。

## Phase 5 — 验证

- 各 phase targeted pytest；动报告/知识前端渲染则 `npm run type-check`（KnowledgePanel/report 视图需适配新 section 与表格）。
- 两 archetype 真实 E2E 各跑一条：
  - landscape（"AI硬件主流产品及趋势"）：core 竞品三件套齐全、报告含分层地图+逐竞品画像+三件套矩阵+定位、证据无 spam、QA 不再"空心通过"。
  - comparison（如"AI编程工具有哪些/对比"）：全部竞品三件套 + head-to-head 矩阵 + 我方位置。

## 范围与风险

- 不引入新依赖；改动集中在 agent 节点 + schema + prompt + qa，复用现有 knowledge 持久化与覆盖状态。
- 统一骨架是较大的 writer/analyst 契约变更（section 改为强制模板、矩阵/画像改为代码确定性渲染），但消除了"报告结构靠 LLM 随机发挥"的不稳定性。
- 报告为 Markdown，2x2 定位以结构化文本呈现，不渲染真实图表（如需图表是后续前端工作，不在本 plan）。
- quick 档 `max_dimensions=3` 恰好容纳三件套；逐竞品画像更厚可走 deep 档。
- E2E 重跑依赖搜索 provider 配额（Tavily 可缺，Bocha/Serper 兜底）。
