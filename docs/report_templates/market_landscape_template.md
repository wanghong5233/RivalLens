# Market Landscape Report Template

适用：用户问“某赛道全景、趋势、机会、主要玩家、是否有空间”。

不适用：用户点名多个产品要求逐项对比。那类走 vendor assessment / head-to-head comparison。

## 输出目录

```text
# {market_scope}{category}市场全景与趋势报告

## 1. 核心判断
## 2. 市场定义与分析边界
## 3. 市场规模、增长与驱动因素
## 4. 细分赛道与应用场景
## 5. 竞争格局
## 6. 关键玩家分析
## 7. 产业链与生态位
## 8. 机会窗口与主要风险
## 9. 战略建议
## 10. 方法论与证据边界
```

## Section Contract

| Section | 必须回答 | 禁止 |
|---|---|---|
| 核心判断 | 市场阶段、领先玩家组、机会、风险、建议方向 | 罗列数据点；把证据摘要当结论 |
| 市场定义与分析边界 | 本报告算什么品类；排除什么；为什么排除 | 用户没说 AI 眼镜时自动收窄到 AI 眼镜 |
| 市场规模、增长与驱动因素 | 规模、增速、出货/收入、驱动、约束；无数据则说明缺口 | 用“发展迅速、前景广阔”替代指标 |
| 细分赛道与应用场景 | 类型、应用、客户场景、区域 | 把公司名单当细分 |
| 竞争格局 | 玩家组、地位、近期动作、竞争变量 | “直接竞品/替代方案/上游供应商”作为用户可见一级结构 |
| 关键玩家分析 | 只覆盖命中目标品类证据的玩家；每个玩家写 role、proof、move、risk | 用手机/云/存储证据证明 AI 硬件能力 |
| 产业链与生态位 | 上游组件、中游制造、下游渠道、生态控制点 | 把上游供应商塞进终端玩家矩阵 |
| 机会窗口与主要风险 | 机会、触发条件、阻碍、证据 | 无证据的宏大建议 |
| 战略建议 | 角色、动作、前置条件、预期影响 | 与前文判断无绑定的通用建议 |
| 方法论与证据边界 | 收录标准、排除标准、数据缺口、证据日期 | 只写“数据不足” |

## Evidence Gate

| Gate | 规则 |
|---|---|
| Category relevance | `company + target_category` 必须同时命中。只命中公司不算。 |
| Product evidence | 产品名、发布、销售、规格、价格、应用案例至少命中一项。 |
| Pricing evidence | 定价必须属于目标品类产品。普通手机价格不能算 AI 硬件定价。 |
| Feedback evidence | 反馈必须来自目标品类产品或明确使用场景。公司客服/通用产品评价不算。 |
| Watchlist | 只有传闻、招聘、投资、媒体猜测的玩家进入 watchlist。 |

## Analyst Workbench

以下内容可以存在于 `content_json` 或 appendix，不作为默认正文一级 section：

| Workbench block | 面向用户的归宿 |
|---|---|
| role layering map | 竞争格局中的玩家组表 |
| competitor profiles | 关键玩家分析 |
| feature/pricing/feedback matrix | 附录：证据矩阵 |
| 2x2 positioning map | 有评分方法时进入竞争格局；否则不渲染 |
| missing coverage table | 方法论与证据边界 |

## AI 硬件示例边界

用户输入：`AI硬件全景与趋势`

不得自动改写成：`AI眼镜市场全景`

可以在“细分赛道”中包含：

| 细分 | 例子 |
|---|---|
| AI 眼镜 / 智能眼镜 | Meta Ray-Ban、XREAL、Rokid、RayNeo |
| AI PC / 端侧计算终端 | 带 NPU 的 PC、开发套件 |
| AI 手机与终端 OS | 只有用户明确包含手机时进入主分析 |
| 机器人 / 具身智能硬件 | 消费机器人、工业机器人 |
| 车载 AI 硬件 | 车机、座舱、感知终端 |
| 上游组件 | SoC、光学、传感器、ODM |

若检索结果主要集中在 AI 眼镜，报告必须写：

```text
本轮公开资料对 AI 眼镜覆盖最充分；其他 AI 硬件细分证据不足。
以下趋势判断以 AI 眼镜为主要样本，不代表整个 AI 硬件市场。
```

## Quick Depth 最低标准

| 项 | 最低要求 |
|---|---|
| 市场边界 | 明确 included / excluded |
| 细分 | 至少 3 个细分；证据不足时标缺口 |
| 玩家 | 至少 3 个目标品类相关玩家，否则降级为 preliminary scan |
| 证据 | 每个主玩家至少 2 条目标品类证据 |
| 结论 | 至少 3 条非模板化判断 |

## Fail Closed

以下情况不得 `approved`：

- 主玩家证据不命中目标品类。
- 定价/口碑来自非目标产品，却被标为 `complete`。
- 用户问大赛道，报告无声明地收窄成单一细分。
- 输出中出现大面积 `未知 / 未核验 / 未找到可核验证据` 表格。
- 2x2 无评分方法、无维度定义、无数据来源。
