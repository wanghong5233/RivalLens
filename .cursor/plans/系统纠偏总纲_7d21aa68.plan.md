# RivalLens 系统纠偏总纲(活的一级 plan)

> 这是一级 plan,不是普通文档。闭环:每个阶段(todo)= 一个任务 → 指定二级 plan 去 build → 二级验证无误回写本总纲 → 二级执行中发现新结构性问题则迭代纠正本总纲。证据来自 run_4820c8cc8911 容器日志 + 对 [backend/app](backend/app) 的只读审计,引用带 file:line。

## 命名体系(统一为阶段主轴)

- 阶段(一级 todo):`S0`-`S5`,按依赖顺序推进,前一阶段 parity 稳定再开下一阶段。
- 问题条目:`SX-N` + 性质标签(`[正确性]`/`[可观测]`/`[数据质量]`/`[成熟度]`)。
- 二级刀:`SX-A`/`SX-B`(二级 plan 内的原子提交单元)。
- 旧编号映射:A1-A4→S0-*;C1/C2→S1-*;B1-B9→S2-*;C3→S3-1、A5→S3-2;C4-C10→S4-*;D1→S5-1。

## 0. 一句话结论

Harness 已接入主链路,但校验层曾是"硬拒绝"而非"归一化"(已在 S0 修复)。剩余问题:默认维度/上限散落多处无单一事实源(S1)、可观测"够看流程不够看内容与成本"(S2)、discovery 跑题与合成证据污染溯源(S3)、大量 naive/硬编码/双轨(S4)、QA promoted enforcement 在后台 run 失效(S5)。

## 1. 主链路实证(run_4820c8cc8911)

- supervisor harness 5 迭代失败 3 次(已由 S0 消除):iter2 `topics: at most 8 items, not 10`;iter3 `dimension must match ^[a-z]...`;iter5 `section_id must match ...`。每次失败=3×LLM 调用+降级。
- discovery 出 10 个离散竞品与查询跑题;discovery 上限 10、batch 上限 8 → 静默丢 2,无可观测字段。

## 4. 活文档增补(执行中发现,新→旧)

### 4.1 S0 收尾(已完成)

S0-1..S0-4 已落地(见 §2 S0)。附带清理 harness 推广遗留测试债:test_researcher_subgraph/dispatcher 的 stale `get_llm_client` patch 改到 `service.llm.harness.get_llm_client`。提交:`60714f3`/`de375ab`。验证:docker 全量 `pytest tests` = 221 passed / 1 failed(唯一失败 = S5-1,正交)。本地 Windows 另有 9 个 async-postgres e2e 因 ProactorEventLoop 红,非代码 bug,docker 全绿。

### 4.2 S5-1 QA enforcement 后台失效(新发现,源自 S0 收尾全量验证)

现象:[test_smoke.py](backend/app/tests/test_smoke.py) `test_promoted_qa_rule_blocks_then_writer_redo_passes` 首轮 `qa_outcome` 实为 approved,期望 rejected;同类 enforce/visible 测试通过 → enforcement 主链路本身可用。根因(待 S5 二级 plan 精确定位):加载链路 `_load_promoted_qa_rules_from_skill_store()`([qa/engine.py](backend/app/service/qa/engine.py):180-196)在后台 task `count=0`;mock 覆盖 conftest `_FakeLLMClient` 无 analyst/extract/qa-semantic 分支致整链降级。

## 6. 方法论(双层文档 + PIV + 活文档闭环)

进入某阶段:新 session → 详细调研该段代码 → 产出该阶段二级 plan(刀/文件/改法/Verify,按"单一关注点·同风险·共享验证"分组)→ 逐刀 PIV,一刀一组原子提交;动手前先跑全绿快照作 parity 锚,同一刀连失败 3 次则 revert 重拆;阶段完成或发现新结构性问题 → 回写本总纲。详见 [docs/private/engineering-playbook/03-incremental-refactor-layered-piv.md](docs/private/engineering-playbook/03-incremental-refactor-layered-piv.md)。
