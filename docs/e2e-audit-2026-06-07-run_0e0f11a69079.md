## 根因分析

### R1 / R2 / R5 同源：维度命名空间中英割裂 + 重写决策丢上下文

- **R2/R5**：`metrics/engine.py` 的 `expected_dimensions` 来自 plan_tree（中文维度名），`downstream_dimensions` 来自 comparison/conclusion/report 的 section_id（英文）。两个集合求交恒为空 → `dimension_coverage_rate=0.0`。S4 改了信号源，但没统一中英词表，错位依旧。
- **R1**：QA 首轮打回后，supervisor 第二次 `Write` 决策（iter4）的 `tool_args` 只带了 `sections:["differentiation"]` 且 `template_id:null`，丢失了首轮的 4 章节 + `executive_briefing` 模板。writer 忠实按缩减后的契约只写了 1 章节。这是 supervisor 重写 args 构造逻辑的缺陷，不是 writer 的问题。

### R3：round1 warning 放行是显式设计，但门槛过宽

QA round0 blocking、round1 warning accept 是 S5 既定门控。问题在于：重写后数字仍无据时，系统选择"warning 放行 + metadata 记录"而非"降级为定性表述或区间"。对老板级 ToB 报告，裸精确数字（62.7%、$40）即便有 metadata 也会被当成事实读取。

### R6 / R7：来源质量门只判文本形态，不判来源权威性与竞品匹配

- **R6**：S6 的 `is_low_semantic_text` 针对过短页面、导航样板、登录组件、`---` 残片，但 OpenAlt 这类"登录头 + 长 SEO 目录正文"页面文本量足够、不命中低语义门；纯图片 markdown（`![alt](url)`）也未被识别为低语义。
- **R7**：当前 gate 完全不判"source 是否一手/官方"与"quote 是否与目标竞品匹配"。结果 pricing/enterprise 维度大量引用泛 B2B 计费站点和第三方目录，与 R3 的数字错配、引用错配（Windsurf 章节引用 Cursor 治理证据）形成因果链。

### 运行版本裁决（推翻并行审计的环境假设）

并行审计把 S4/S6 未达标归因于"容器跑旧镜像"。实测：`docker compose exec rivallens_api` 下 `/app` 为 9p bind-mount 主机 E 盘，代码路径是 `/app/service/...`（并行审计 grep 用的 `/app/app/...` 或省略路径，故未命中）。容器内可直接 grep 到 `downstream_dimensions`(engine.py:232)、`source_quality_floor`(researcher.py:347)、`is_low_semantic_text`/`source_blocklist_reason`(source_quality.py:49/71)。故 **AUDIT-003 的"版本不一致"假设证伪**；S4=真实逻辑回归，S6=覆盖规则不足。下次 E2E 前的环境校验命令应改用正确路径（见文末）。

## 下一轮建议（按优先级）与验收标准（DoD）

1. **R1 P0（=AUDIT-002）**：修 supervisor 重写决策构造，QA 打回重写时必须沿用首轮 resolved `target_sections` + `template_id`，禁止章节集收窄；QA 增加"retry target_sections 不得小于原始写作契约"的校验。
   - DoD：QA rejection 后 writer retry 的 target_sections ⊇ 首版；重写后 `section_count`/`char_count` 不低于被打回版；除非人工改 plan。
2. **R2 P0（=AUDIT-003）**：统一维度命名空间——plan_tree 维度与 comparison/conclusion/report section_id 用同一词表（建议英文 section_id 为准，plan 侧存中→英映射），让 `dimension_coverage_rate` 真实可算。
   - DoD：同一 run 的 `dimension_coverage_rate ≥ 0.5`，curator 不因 coverage 误跳过；容器内 `metrics.engine` 计算链确认用映射后词表。
3. **R3 P1（=AUDIT-001）**：数字 claim 重写后仍无据时，从 warning 放行升级为"强制降级"——QA 或 writer serializer 把无据精确数字改写成定性/区间表述；战略建议类数字显式标注为 proposal 而非 factual claim。
   - DoD：final approved report 的 `qa_unsupported_numeric_claims` 为空，或 run/report status 标为 `completed_with_warnings` 且前端突出展示不可直接采信。
4. **R6 P1（=AUDIT-004）**：扩展来源质量门——识别"登录头 + SEO 目录页"与纯图片 markdown；新增 source authority score 与 competitor-source 匹配 gate。
   - DoD：researcher dropped reasons 能看到 `source_blocklist`/`low_semantic`；抽样 evidence 不含 sign-in header、纯图片残片、明显竞品错配 quote。
5. **R7 P1（=AUDIT-005）**：pricing/enterprise/market-size/SLA/compliance 类结论优先官方 pricing page、官方 docs、release note；缺一手来源时 stance 降为 unknown 或定性。
   - DoD：pricing_strategy 每个核心竞品至少 1 条官方 pricing/plan evidence；enterprise_capabilities 区分 official doc 与第三方 article。
6. **R4/R5 P2**：`report_section_coverage_rate` 改用稳定锚（plan 或首轮 target_sections）作分母；`evidence_count_by_dimension` 词表对齐（随 R2 一并解决）。
