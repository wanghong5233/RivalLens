# RivalLens Collector Channels 协议

> 更新时间：2026-05-29

本文定义 Researcher 可调用的采集/知识通道协议。  
目标：保证通道可扩展、可观测、可降级。

## 1. 设计原则

- **统一入口**：所有通道通过 `ChannelRegistry.invoke(action, args)` 调度。
- **结构化返回**：统一返回 `CollectorObservation` + `ToolObservationResult`。
- **错误显式**：通道失败返回结构化错误，不做静默 fallback。
- **可替换**：新增通道不需要修改 Agent 角色边界。

## 2. 通道清单（当前主干）

| action | 用途 | 典型输入 | 典型输出 |
|---|---|---|---|
| `search_web` | 搜索候选来源 | `query`, `max_results?` | snippets（URL + 摘要） |
| `fetch_url` | 拉取网页原文 | `url`, `dimension?` | raw text/html 摘要 |
| `parse_page` | 页面解析抽取 | `html`, `source_url`, `source_title?` | 可抽取文本 |
| `extract_structured` | 结构化证据抽取 | `text`, `dimension`, `competitor_id` | evidence-ready snippets |
| `load_skill` | 按 skill_id 加载技能摘要 | `skill_id` | 描述、tags、available_files |
| `read_skill_file` | 读取技能支持文件 | `skill_id`, `filename` | 文件内容 |

## 3. 统一响应形态

```json
{
  "channel": "extract_structured",
  "args": {},
  "result": {
    "snippets": [],
    "metadata": {}
  }
}
```

约定：

- `snippets` 用于证据候选（最终落库到 `evidence`）
- `metadata` 保留通道级上下文（如 dimension/source_type）
- 失败时由上层记录 error 到 observation log / step payload

## 4. `load_skill` / `read_skill_file` 细节

### 4.1 `load_skill`

输入：

```json
{ "skill_id": "evidence-must-cite-source" }
```

输出（命中）：

```json
{
  "skill_id": "evidence-must-cite-source",
  "description": "...",
  "tags": ["qa", "citation"],
  "applies_to": "qa_rule",
  "available_files": ["examples.md"]
}
```

输出（未命中）：

```json
{
  "error": "skill_not_found",
  "available_skills": []
}
```

### 4.2 `read_skill_file`

- 仅允许读取技能目录内文件；
- 路径越界（`../`）必须拒绝；
- 文件不存在返回结构化错误。

## 5. 可观测字段

每次通道调用至少记录：

- `action`
- `dimension`（若有）
- `competitor_id`（若有）
- `has_error`
- `latency_ms`（可选）

这保证可以在 trace 中定位“为何没有证据”和“为何触发降级”。

## 6. 降级与恢复

- `search_web` 失败：可切 `fetch_url` / `reference_urls`
- `fetch_url` 失败：可回到 `extract_structured` 处理已有文本
- `load_skill` 失败：不阻塞主流程，Researcher 继续通用采集

## 7. 扩展规范

新增通道必须补齐：

1. action 名称与输入 schema
2. 错误语义（可重试 / 不可重试）
3. 结果映射到 snippets/metadata 的规则
4. 对应测试（通道单测 + 至少一个端到端覆盖）
