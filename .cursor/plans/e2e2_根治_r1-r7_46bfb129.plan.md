## 根治原则

零新依赖、不需任何 key。沿用现有 LLM-first + 代码护栏架构：语义判断交 Qwen，确定性代码负责契约/词表/grounding/门控。参考成熟范式：GSAR 三级决策（proceed/regenerate/replan，不盲目 warning 放行）、living contract（写作契约持久复用）、Trafilatura 式 boilerplate 启发式（class/density 负信号）。

依赖关系：R1 与 R2 在 supervisor/planner 维度契约上耦合，先做且同批；R3/R6/R7 相互独立可并行推进。

## Stage A（P0）R1 — QA 打回重写不得塌缩写作契约

根因：[supervisor.py:499-525](backend/app/agents/nodes/supervisor.py) 的 `qa_reject_to=="writer"` 分支硬编码 `template_id=None` + 临时重算 `fallback_sections` 重建契约，完全不读首版 writer step 已持久化的 `target_sections`（[writer.py:627-634](backend/app/agents/nodes/writer.py) 存了，[qa.py:30-39](backend/app/agents/nodes/qa.py) 的 `pending_review_target_step_id` 能精确定位）。

改法：
- 在 supervisor 的 writer-reject 分支，从 `pending_review_target_step_id` 指向的 writer Step 读回 `payload["target_sections"]` 与原始 `template_id`，作为重写契约。
- 强制 `重写 sections ⊇ 首版 sections`（取并集），`template_id` 沿用首版，禁止收窄为单章节。
- 读不到首版 payload 时（旧 run 兜底）才退回现有 `fallback_sections` 逻辑。
- 可观测：决策日志记录 `rewrite_sections_source=prior_writer_step|fallback` 与 sections 数量。

验收 DoD：
- 单测：构造 QA reject 场景，断言重写 Write 决策的 sections ⊇ 首版且 template_id 一致。
- 真实 E2E：QA 打回后 v2 报告 `section_count`/`char_count` 不低于 v1。

## Stage B（P0）R2 — 统一维度命名空间（英文 snake_case 契约）

根因：不是两套词表，是一套英文契约 + 一个中文泄漏点。[agent_outputs_pipeline.py:191-199](backend/app/schemas/agent_outputs_pipeline.py) 的 `PlannerOutput.parse_llm_content` 唯独不调 `validate_dimension`，planner LLM 对中文 query 产出中文 `focus_dimensions` 原样落库；[metrics/engine.py:76-81](backend/app/service/metrics/engine.py) 读它与英文 section_id 求交恒空 → `dimension_coverage_rate=0.0`，curator 跳过（[skill_curator/tasks.py:170](backend/app/service/skill_curator/tasks.py)）。

改法（源头统一，不在 metrics 加翻译表）：
- planner prompt 明确要求 `focus_dimensions` 必须是英文 snake_case，给出 canonical 维度建议清单（product_positioning / pricing_strategy / enterprise_capabilities / market_differences 等）。
- `PlannerOutput.parse_llm_content` 补 `validate_dimension` 归一化，与 comparison/conclusion/report 走同一契约校验。
- 兜底：校验后 `focus_dimensions` 为空时，用现有 `DIMENSION_HINTS` 或默认英文维度回填，避免空集反向触发 R1 的 fallback 塌缩（这也是 A/B 同批的原因）。

验收 DoD：
- 单测：中文 focus_dimensions 输入经解析后变英文 snake_case 或被合法兜底，非空。
- 真实 E2E：同一 run `dimension_coverage_rate >= 0.5`，curator 不再因 coverage 跳过。
- 连带 R5：`evidence_count_by_dimension` 词表对齐。

## Stage C（P1）R3 — QA 数字门控 GSAR 化 + writer 重写带反馈

根因三重叠加：
- [qa/engine.py:293-303](backend/app/service/qa/engine.py) round1 只看 `qa_rejection_count>=1` 就无条件降 warning，不验证数字是否真被修正；[engine.py:591-610](backend/app/service/qa/engine.py) 还有第二个 `evidence>=12` 的整体 warning 旁路。
- writer 重写 prompt 不带 `qa_reasons`（[writer.py:530](backend/app/agents/nodes/writer.py)、`build_writer_user_prompt` 不接受该字段），等于盲改。
- `WRITER_SYSTEM_PROMPT`（[prompts.py:417-447](backend/app/service/llm/prompts.py)）无"数字必须来自证据"约束；unsupported 列表只进 QA step payload，不进 report/run status，用户不可见。

改法（轻量采纳 GSAR，不引入 NLI 模型）：
- writer 重写时把 `qa_reasons` + `unsupported_numeric_claims`（含 section、无据原因）注入 writer user prompt，明确指示"删除或定性化这些无据数字"。
- `WRITER_SYSTEM_PROMPT` 增 factuality 约束：精确数字（%/金额/时长）必须有同数字证据支撑，否则改写为定性/区间或标注为 proposal。
- QA 门控改三级语义：重写后比对 unsupported 集合——若已清空则 proceed；若数字仍无据但**确实减少/被定性化**可 warning；若**毫无改善**则继续 blocking（受 `K_max` 轮次预算保护，达上限改为 report status=`completed_with_warnings` 而非静默 approved）。
- `qa_unsupported_numeric_claims` 写回 report metadata / run status，前端可标注"含未核验数字"。

验收 DoD：
- 单测：覆盖三级决策（清空→proceed、改善→warning、无改善→blocking/降级 status）；writer prompt 含 qa feedback 字段。
- 真实 E2E：final approved report 的 `qa_unsupported_numeric_claims` 为空，或 run/report status 显式 `completed_with_warnings`。

## Stage D（P1）R6 — 来源质量门补齐漏判

根因：[source_quality.py:49-83](backend/app/service/collector/source_quality.py) 导航门是 `navigation_hits>=3 AND words<80` 双条件，长 SEO 目录页（openalt.pro，"Sign in Home/Tools/Coding"）绕过；登录短语集合是固定 phrase 不含 "sign in home"；无 `![](...)` 图片 markdown 检测；入库点 `RESEARCHER_LOW_SEMANTIC_MIN_CHARS=0`（[researcher.py:26](backend/app/agents/nodes/researcher.py)）把 too_short 门关了。

改法（Trafilatura 式启发式，纯规则）：
- 新增图片/链接密度检测：quote 主体是 `![](...)` 图片 markdown 或链接占比过高 → 判低语义。
- 登录目录页检测：拆开导航门双条件，对"开头即登录/导航样板 + 高链接密度 + 目录式短行堆叠"独立判定，扩充导航短语集（Sign in / Home / Tools / Coding 等组合）。
- 复核 `RESEARCHER_LOW_SEMANTIC_MIN_CHARS=0` 是否应给一个合理下限（与 fetch_url 门对齐），避免入库阶段完全关掉 too_short。
- zero-evidence floor 兜底（[researcher.py:335-350](backend/app/agents/nodes/researcher.py)）保留但标记，不让它放行明显的登录/图片残片。

验收 DoD：
- 单测：openalt 登录目录页样本、纯图片 markdown 样本被 `is_low_semantic_text` 判低语义。
- 真实 E2E：researcher dropped reasons 出现 `low_semantic`/`source_blocklist`；抽样 evidence 无 sign-in header、无纯图片残片。

## Stage E（P1）R7 — 来源权威性 + competitor-source 匹配

根因：[parse_page.py:13-33](backend/app/agents/tools/parse_page.py) 的 `infer_source_type` 两处调用全传 `official_hosts=None`（[search_web.py:101](backend/app/agents/tools/search_web.py)、[fetch_url.py:130-133](backend/app/agents/tools/fetch_url.py)），官方域名识别永久失效，`docs`/`official_site` 永不被赋值；全链路无 source authority、无 competitor-source 域名匹配（$39/user 来自无关泛 B2B 站点不会被发现）。

改法：
- 为每个竞品维护官方域名集（从 run competitors / reference_urls / 简单启发式推导），把真实 `official_hosts` 传入 `infer_source_type`，让 `official_site`/`docs`/`pricing_page` 正确分类。
- 入库点加 competitor-source 弱匹配信号：source_url 域名与目标竞品官方域名/竞品名是否相关，写入 span 作为 authority 标记（不硬过滤，作为低置信标注 + 可观测）。
- pricing/enterprise 维度优先级提示：researcher source routing 倾向官方 pricing/docs；缺一手来源时 analyst/QA 对该维度 stance 倾向 unknown 或定性。

验收 DoD：
- 单测：官方域名 url 正确分类为 official_site/pricing_page；competitor-source 不匹配被标注。
- 真实 E2E：official_site/docs/pricing_page 占比上升；pricing_strategy 维度核心竞品有官方来源或显式降级。
